## 原始计划与根因

结论先说：这两个问题应当一起处理，顺序是先清理 High/Low 的重复轨迹状态，再限制光流错误传播，最后用质量下降触发提前检测。原预计工程量约 10–15 个开发日。

源码中已经确认几个直接根因：

- `currentTracks()` 直接拼接 stable 与满足两次低分辨率命中的 provisional，没有最终状态去重。
- provisional 两次命中即输出、最长保留 30 帧；stable 最长可保留 90 帧。
- 低分辨率匹配允许面积差 4 倍，陈旧轨迹 IoU 门槛低至 0.06，geometry blend 权重最高 0.75。
- LK 光流单目标只需 2 个有效点，forward-backward error 可达 5 px，且只有全局质量，没有逐轨迹质量。
- AuthorityTracker 中的 detector score 不随连续光流帧衰减，错误轨迹可以长时间存活。
- High/Low 的动态 stride 被 `max(current_stride, base_stride)` 限制，质量恶化时不能把低分辨率检测间隔缩短到 urgent stride。

相关实现集中在 [video_inference_high_low.cpp](../../yolo_onnx_cpp/video/video_inference_high_low.cpp) 和 [optical_flow_tracker.cpp](../../yolo_onnx_cpp/video/optical_flow_tracker.cpp)。

## 一、优化目标

以当前 pooled 结果为基准，设置以下验收门槛：

| 指标 | 当前 | 目标 |
| --- | ---: | ---: |
| precision | 0.5048 | ≥ 0.62 |
| recall | 0.8684 | ≥ 0.82 |
| F1 | 0.6384 | ≥ 0.70 |
| predictions/labels | 1.72 | ≤ 1.25 |
| FP | 29,307 | ≤ 18,000 |
| weak-tracked precision | 0.5025 | ≥ 0.62 |
| weak-tracked mean IoU | 0.8588 | ≥ 0.88 |
| pooled FPS | 31.34 | ≥ 28 |
| 单场景 recall | 最低 0.805 | 不低于 0.75 |

优化目标不是简单压低输出数量，而是在 recall 最多下降约 5 个百分点的前提下，大幅减少重复框和漂移框。

## 二、阶段 1：建立重复与漂移诊断指标

先增加诊断，不改变算法行为。

新增内部统计：

- stable/provisional 当前数量。
- provisional 创建、晋升、超时、被去重数量。
- stable-stable、stable-provisional、provisional-provisional 重复数量。
- 每条轨迹距最近 detector 更新的帧数。
- 每条轨迹连续 flow-only 帧数。
- 相对最近检测框的中心漂移、宽高比、面积倍率。
- 因有效点不足、FB error、运动离散、边界退出而拒绝的光流轨迹数。
- 触发 urgent low/high detection 的原因和次数。

响应 JSON 只增加字段，不删除或修改现有字段。重新运行三段基准，确保优化前问题可以被精确归因。

## 三、阶段 2：修复 High/Low 重复和过量输出

### 2.1 在内部状态层去重

不能只在最终输出做 NMS，否则重复状态仍会参与下一帧匹配。每次 high-res、low-res 和 replay 更新后，对 tracker 内部状态做 consolidation：

优先级固定为：

1. 最近被高分辨率确认的 stable。
2. 最近被低分辨率匹配的 stable。
3. 高分辨率待确认的 provisional。
4. 普通 provisional。
5. 纯光流维持的陈旧轨迹。

去重规则初始值：

- 同类别且 IoU ≥ 0.45：判定重复。
- 同类别、中心距离 ≤ 较大框对角线的 0.25，且面积比 ≤ 2：判定重复。
- 不同类别但 IoU ≥ 0.70：保留 authority 更高的一条。
- stable 与 provisional 重复：stable 保留，provisional 删除。
- provisional 互相重复：保留连续命中更多、score 更高、更新更近的一条。
- stable 互相重复：保留 authority 更新时间更近的一条，并合并低/高 miss 状态。

最终 `currentTracks()` 再执行一次只读输出抑制，作为安全网。

### 2.2 收紧 provisional 生命周期

当前“两次命中即可输出、保留 30 帧”过于激进，调整为：

- 至少连续 3 次低分辨率命中才允许输出。
- 如果 score ≥ 0.60，可允许连续 2 次命中。
- 连续 2 次低分辨率未匹配后停止输出。
- 12 帧未更新即删除，而不是等待 30 帧。
- provisional 与 stable 几何接近时不新建；即使类别冲突，也优先视为已有 stable 的低分辨率分类噪声。

### 2.3 收紧低分辨率匹配和几何融合

替换当前过宽松的面积比与 stale IoU：

- 最大面积比由 4.0 收紧到 2.0。
- fresh stable：IoU ≥ 0.20，或中心兼容分 ≥ 0.65。
- stale stable：不再允许单独依靠 IoU 0.06 匹配；仍需满足面积和中心联合约束。
- fresh geometry blend 权重由 0.60 降到 0.35。
- stale geometry blend 权重由 0.75 降到 0.50。
- 单次低分辨率更新后面积变化限制在 0.67–1.50 倍。
- stale 轨迹可放宽至 0.50–2.00 倍，超过则拒绝此次 geometry 更新并触发 authority refresh。

这一步主要解决大框、边缘框和重复 traffic sign/light。

## 四、阶段 3：限制光流漂移传播

### 3.1 改为逐轨迹光流质量

扩展 `WeakTrackResult`，为每条 track 返回：

- sampled/valid point 数量。
- valid point ratio。
- median forward-backward error。
- dx/dy 中位数。
- 位移 MAD 或四分位差。
- 相对 bbox 对角线的运动比例。
- 是否发生边界裁剪。

逐轨迹接受门槛初始值：

- 有效点不少于 4 个，而不是当前 2 个。
- valid ratio ≥ 0.50。
- median FB error ≤ 2 px。
- 位移离散度 ≤ bbox 对角线的 0.08。
- 单帧中心位移不能超过 bbox 对角线的 0.35；超过则拒绝，而不是直接移动框。

坏轨迹不应因为全局平均质量尚可而继续传播。

### 3.2 增加 flow-only age 与置信度衰减

在 `AuthorityTrack` 和 `ProvisionalTrack` 中增加：

- `last_detector_frame_index`
- `flow_only_age`
- `flow_confidence`
- `last_valid_flow_frame_index`

规则：

- 高/低检测成功匹配后，`flow_only_age=0`。
- 可靠 direct flow 每帧增加 age，并轻微降低 flow confidence。
- global motion 更新采用更快衰减。
- flow-only 超过 16 帧后停止输出。
- 最多保留到 24 帧等待检测恢复，之后删除。
- detector score 与 flow confidence 分开保存，避免把旧模型分数当作当前可信度。

这样可以直接解决“目标离开后仍保留数秒”的问题。

### 3.3 约束边界和尺度

光流只负责平移，不允许修改宽高。每次更新后增加：

- 可见面积低于原框 50% 时标记为 exiting。
- 连续 2 帧 exiting 后停止输出。
- 框中心已越出画面时立即删除。
- 低分辨率融合造成的宽高变化必须通过上一阶段的比例门控。

### 3.4 改进全局运动估计

不新增第三方依赖，继续使用 OpenCV：

- 全局运动角点优先从检测框以外的背景区域选取。
- 使用位移中位数，并增加 MAD/inlier ratio。
- 背景有效内点不足时禁止 global flow fallback。
- severe quality drop 时，direct flow 也必须逐轨迹通过质量门控，不能仅关闭 global motion。

## 五、阶段 4：质量下降时提前重新检测

当前 dynamic stride 的 urgent 结果被 base stride 下限抵消，需要修正：

- High/Low 的 low-res 调度直接使用 `current_stride`，允许 severe 时缩短到 2 帧、complex 时缩短到 3 帧。
- 以下情况触发下一帧 low-res 检测：
  - 超过 20% 轨迹的逐轨迹 flow 不合格。
  - 出现 scale jump 或 velocity jump。
  - provisional/stable 重复数量突增。
  - flow-only age 接近 16 帧。
- 以下情况触发下一次 worker 可用时的 high-res authority refresh：
  - 同一 stable 连续两次 low-res 几何被拒绝。
  - 大量框被 duplicate suppression。
  - severe flow 连续两帧。
  - 类别冲突或面积突变。

紧急检测只在质量恶化时触发，避免把 High/Low 重新变成全帧高分辨率推理。

异步 high-res 结果 replay 时必须执行同一套逐轨迹质量门控、状态去重和生命周期规则，保证在线结果与 replay 结果一致。

## 六、测试计划

### 单元测试

在 [authority_tracker_policy_test.cpp](../../yolo_onnx_cpp/test_cpp/authority_tracker_policy_test.cpp) 增加：

- stable 与 provisional 重叠时只输出 stable。
- 同目标不同类别低分辨率检测不会生成重复 provisional。
- 两个 stable 被同一 high-res 检测确认后合并。
- provisional 未达到 3 次连续命中不输出。
- provisional 连续丢失后停止输出并过期。
- flow-only 超过 16 帧停止输出、24 帧删除。
- 低分辨率面积膨胀超过上限时拒绝更新。
- 边界退出轨迹及时删除。
- replay 前后去重结果一致。

光流测试增加：

- 只有 2 个点时拒绝。
- FB error 过高时拒绝。
- 点位移方向不一致时拒绝。
- 背景点不足时不使用 global motion。
- 可靠平移保持 bbox 尺寸不变。
- 雨滴或局部噪声不应推动整个框漂移。

## 七、实施顺序

1. 诊断指标与回归测试。
2. 内部状态去重和 provisional 生命周期。
3. 低分辨率匹配及 geometry 门控。
