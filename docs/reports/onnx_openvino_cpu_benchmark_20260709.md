# ONNX Runtime vs OpenVINO CPU Benchmark

测试日期：2026-07-09

## 结论

在当前 `yolo_onnx_cpp` 服务端实现和同一模型、同一视频、同一推理策略下，OpenVINO CPU 明显快于 ONNX Runtime CPU。

| 指标 | ONNX Runtime | OpenVINO | OpenVINO 相对变化 |
| --- | ---: | ---: | ---: |
| 视频整体 FPS | 3.123 | 5.181 | 1.659x |
| 总处理耗时 | 9606.156 ms | 5799.160 ms | 降低 39.6% |
| 模型推理总耗时 | 8915.298 ms | 4750.263 ms | 1.877x |
| 模型推理 p50 | 297.331 ms | 157.688 ms | 1.886x |
| 模型推理 p95 | 331.805 ms | 225.667 ms | 1.470x |
| 模型推理 p99 | 346.464 ms | 261.163 ms | 1.327x |
| 端到端 p50 | 315.151 ms | 183.540 ms | 1.717x |

简要判断：OpenVINO 的主要收益来自模型推理阶段；在本次 30 帧全帧同步推理测试中，模型推理 p50 降低约 47.0%，整体视频处理吞吐提升约 65.9%。

## 注意事项

- 两个后端都读取同一个 `.onnx` 模型文件，不比较 OpenVINO IR 离线转换产物。
- `thread_num: 4` 当前显式作用于 ONNX Runtime 的 intra-op threads；OpenVINO 后端没有在代码中显式设置 `ov::inference_num_threads`，因此 OpenVINO 使用 CPU 插件默认线程策略。
- 本次测试是服务端接口路径实测，包含视频读取、预处理、模型推理、跟踪、JSON 响应等开销；核心性能差异应优先看 `infer_*` 指标。
- benchmark 结束后确认 8080 端口无服务进程残留。
